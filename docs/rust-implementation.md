# Rust 实施与验收

实施使用测试审查阶段的原 Rex/Pi 会话。每条线从共同基线快进自己的 worktree；整合者维护 `cli.rs`、`transport.rs`、`lib.rs`、依赖和锁文件。公共行为看 [迁移合同](rust-migration.md)，发现冲突先报告，不在各线单独决定。

## 第一批实现：本地路径和合成输入

| 功能线 | 所有权 | 第一批交付 | 后续接线 |
|---|---|---|---|
| identity | `src/identity.rs`、必要时 `src/identity/`、本线测试 | `status`、`logout`、本地凭据解析和会话归属；用纯本地用例验证登录参数和失败不改状态 | CAS 验证、会话文件私有写入、按服务续期及 `diagnose` |
| academics | `src/academics.rs`、必要时 `src/academics/`、本线测试 | 课表快照归属、离线筛选与日历导出；非法日期和错误身份先拒绝 | 注入教务响应和研究生页面源；再接平台浏览器能力 |
| homework | `src/homework.rs`、必要时 `src/homework/`、本线测试 | 课程与作业参数、提交门禁；把上传/提交零次、一次及未知结果写成可运行的进程内测试 | 课程分页、作业列表/详情/下载与实际会话适配 |
| campus | `src/campus.rs`、必要时 `src/campus/`、本线测试 | 输入边界、宿舍设置优先级、匿名图书馆响应解析；用已有夹具验收 | 统一会话适配后的电费、通知和饭卡 |
| lifecycle | `src/lifecycle.rs`、必要时 `src/lifecycle/`、本线测试 | `update` 输入及发行物选择、只针对临时副本验证卸载保护 | 下载完整性、回滚、Windows 进程退出后的替换与实机验收 |

## 开发与审查

1. 保留每线 `commands()` 和 `run()` 入口；在调用校园服务前校验业务参数。能在一个文件清楚表达就不加目录；数据分派留在所属模块，不堆进 `cli.rs`。
2. 先读本线迁移清单。让本轮命中的用例变绿；为新接入的响应和副作用补夹具测试。生产路径不得新增模拟环境变量。只使用隔离目录与合成响应，不打开真实校园服务或浏览器会话。
3. 提交前跑 `cargo fmt --check`、`cargo test --locked --offline --lib` 和 `cargo test --locked --offline --test contract_<lane>`。逐项记录通过、尚未实现与未运行项。不要把仍依赖别线的红测改成跳过或用测试绕开。
4. 整合者复跑同一提交，检查命令、数据与副作用边界，核对跨线契约，按依赖合并。共享服务接口只有在出现第二个调用方或已有集成用例时才提取；未接通的 HTTP 适配器不是生产能力。阶段验收不替代最终平台与校园网实测。
