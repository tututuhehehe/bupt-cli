# Rust 迁移合同

Python 对照：`d7c35ef`。该版本的代码和离线测试用来查语义，不作为 Rust 运行依赖。本文列出的有意变化优先于旧测试；发现其余公开行为冲突时交给整合者，别悄悄调整预期。

## 公开入口

最多两级。`login` / `status` / `logout`；`courses`；`homework`（默认列表）/ `show` / `download` / `submit` / `verify`；`schedule`（默认本周）/ `update` / `calendar` / `export`；`exams`；`scores`；`classrooms`；`library search` / `hold` / `ebook`；`electricity` / `buildings`；`notices` / `show`；`card`；`diagnose`；`update`；`uninstall`；`help [命令]`。不提供 `homework list`、`schedule exams` 或 `probe` 作为旧别名。`help`、`--help`、`--version` 保持文本；非交互业务输出默认一个 JSON 文档，分别在 stdout（结果）和 stderr（错误），带 `schema: "bupt.v1"`；`--pretty` 不改变值。保留能沿用的字段、参数和退出码。非法参数在读写业务状态、联网或启动浏览器前拒绝。

## 行为验收

- **身份**：`login` 验证校园凭据，登记显式选择的本科/研究生身份，不预热具体服务。变更凭据时不能拿旧会话证明新密码有效，失败时保留上一次有效登记和会话。已登记的学号、密码和身份统一从本地 `credentials.json` 读取；不读取、不回退到 `BUPT_USERNAME`、`BUPT_PASSWORD` 或 `BUPT_ROLE`。没有有效凭据时，需要登录的命令提示运行 `bupt login`；匿名功能不受影响。凭据文件须限制为当前用户可访问，分别验证 macOS 权限与 Windows 的等价保护。Cookie/token 同样敏感；测试、日志和错误不得携带真实秘密。首次启用可读取旧的账号配置；只复用归属可验证且兼容的旧会话。新会话按学号和身份隔离；旧会话缺身份时，只可重新使用归属学号明确且不按身份区分的部分。`logout` 清掉本地密码和会话，保留课表与设置。
- **续期**：服务按需建立会话；只有明确过期才允许一次自动续期。暂时断网、拒绝密码、限流不是续期信号。研究生不触发本科教务认证；学号或身份切换不复用另一所有者的状态。`status` 只读本机状态，不保留 `--check`；`diagnose` 能联网做公开和会话检查，但不提交密码、不写本地会话。需要授权的检查在会话不可用时标注跳过，公开检查不受影响。`login` 不保留 `--jwgl`。
- **课表**：查询、`schedule calendar` 和 `schedule export` 共用本地优先的取数规则。先确认快照属于当前学号和身份，再判断运行当天（本机日期）是否落在快照的学期日期区间内（含首尾）。没有可用快照或当天不在区间内，才按身份联网获取整个学期的课表和教学周日期。只维护当前学期。区间内不按缓存年龄自动刷新；学期中选退课后用 `schedule update` 主动更新。`--date` 只筛选当前学期，指定日期超出区间时报告范围，不切换学期或把它当作没课。缺失或跨学期时，每次命令最多发起一次自动刷新；失败、数据不完整或结果仍不覆盖运行当天时，保留上一份快照，但不把它当作本学期返回，不据此生成日历。无归属信息的旧快照不能当成当前账号的数据。导出先规范化上游能识别的日期和时间。任一上课场次无法生成有效事件时，指出课程和缺失信息，不生成半份日历或覆盖已有 `.ics`；教师或教室未定可以留空。导出写入成功不因打开文件管理器失败变成导出失败。
- **教务来源**：`exams` 按身份选数据源，输出共同外壳，不伪造考试日期、场次、地点。研究生教务可以依赖已安装的 Chrome，不捆绑浏览器；macOS 和 Windows 均需验证。
- **作业**：没有 `--i-confirm-submit` 不上传、不提交，`--dry-run` 同样不写入。兼容 `6/7` 表示可能已提交但无法确认；先只读核验，绝不自动重发提交请求。`verify` 比对正文/附件时可建立访问会话，但不写校园作业数据。
- **分发**：macOS Apple Silicon 与 Windows x64 分别发布一个原生可执行文件。验证完成后切换到 Rust，不长期保留两套实现。按需保留已有数据字段与可兼容的文件格式；开发和验收用隔离目录，不碰正在使用的 Python 版及其状态。校园网实测等用户通知后进行。更新和卸载只作用于获准的目标；卸载可清理自己的课表，不扩大删除范围，不对跳过项报告为已删除。

## 离线测试边界

- **进程测试**走正式 CLI，验证参数、输出流、退出码及文件副作用。所有状态路径放入临时目录；涉及卸载时始终执行临时副本。测试不要把「没有文件变化」当成「没有发出请求」。
- **服务测试**在 Rust 测试进程内注入 HTTP 传输，回放合成响应并记录所有请求，包括不匹配的请求；无匹配则拒绝，不回退联网。只在有时效逻辑的模块注入时钟；研究生教务另用假页面源，导出用假文件管理器；同类能力复用一份测试工具。正式二进制不暴露模拟会话、时钟、传输的环境变量或命令。
- **写操作**对记录直接断言次数和顺序：未确认或预演时没有上传和提交；已确认至多发一次提交；超时或断连导致结果不明时只允许核验。离线通过不等于校园网或双平台实测通过。

## 初轮：先迁测试

1. 从任务指定的 Python 测试找输入、边界和预期，再对照上面的有意变化。每条迁移或变更至少对应一个 Rust 用例（或记为待实现的集成场景并解释原因）。不搬 Python 私有函数调用和数据结构。
2. 只写任务拥有的 `tests/contract_<lane>.rs`、`tests/fixtures/contracts/<lane>/` 和场景清单 `docs/migration-tests/<lane>.md`。清单标注 Python 测试名或代码位置、覆盖的 Rust 用例，以及暂不能验证的边界。共享 harness 和依赖变更由整合者负责。
3. Rust 集成测试使用共享 `mod contract_support;`：`Sandbox::new()` 隔离家目录、配置和缓存；`.run(&[...])` 捕获进程输出；`.stdout_json()` / `.stderr_json()` 解析单个文档。按语义断言退出码、输出流、字段、禁止的副作用；对现场联网、真实密码、已安装浏览器不可依赖。如基础设施不足，在清单写明所需的最小测试缝，不用永远通过的假测试代替。
4. 交付一个测试提交。`cargo fmt --check` 和 `cargo test --offline --test contract_<lane> --no-run` 要通过；运行目标测试，预期失败应准确指出空实现缺少的行为，不接受编译错误、真实联网、`#[ignore]` 或 `#[should_panic]` 掩盖失败。报告提交号、编译命令、失败分组和未覆盖项，停在测试阶段。
5. 整合者审查用例能否捕获负例、是否符合合同、夹具是否脱敏、是否越界；复跑并合并测试后才派实现。各模块只改分配文件，共享入口、依赖、锁文件及跨平台发布由整合者收口。实现审查需通过格式、Clippy、全套 Rust 离线测试和两平台实际运行；校园网上游验收单独记录为待实测。最后从验收过的命令和输出重写中英文 README、使用说明与项目 CLI Skill。
